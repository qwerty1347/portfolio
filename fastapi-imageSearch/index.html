유사 이미지 검색_

업로드한 이미지의 객체를 판별하여 가장 유사한 이미지들을 반환합니다. YOLOv8 객체 검출 → CLIP ViT-L/14 768차원 임베딩 → Qdrant 코사인 유사도 검색을 단일 API를 구현했하였습니다. lru_cache + lifespan으로 프로세스당 한 번만 로드하였습니다.

01 overview

Celery 워커를 사용한 이유

request
POST /api/v1/image

업로드된 이미지에서 YOLO로 객체 1개 추출 → CLIP 인코딩 → Qdrant Top-5 검색을 한 번의 요청으로 처리. 동기 추론은 모두 asyncio.to_thread로 위임됩니다.

vs
background
embed_fruit_images.delay()

Celery 워커가 storage/images/fruits/를 순회하며 데이터셋을 벡터화·upsert. uuid5(name=path) 결정적 ID로 재실행해도 같은 포인트가 갱신되어 멱등성을 유지합니다.

04 // highlights

기술적 결정

001

의존성 주입 + 모델 싱글톤

get_qdrant_client · get_embedding_model · get_yolo_model을 @lru_cache(maxsize=1)로 감싸 프로세스당 1회만 로드. FastAPI는 Depends로, Celery는 같은 캐시 함수를 직접 호출하여 객체를 재사용하였습니다.

002

lifespan 워밍업으로 콜드 스타트 제거

asynccontextmanager 기반 lifespan에서 부팅 시 Qdrant 클라이언트 · CLIP · YOLO를 미리 로드. 첫 요청에 추론 + 모델 로드가 동시에 발생해 응답이 느려지는 콜드 스타트를 차단합니다. 종료 시 Qdrant client를 명시적으로 close.

006

입력 검증 — bbox 임계치

YOLO가 검출한 객체가 너무 작거나 비율이 비정상이면 임베딩 품질이 떨어집니다. min_size=10px · min_ratio=0.01 임계치로 사전 필터링하고, 미달 시 BusinessException으로 422를 반환해 노이즈가 벡터DB에 들어가지 않게 합니다.
