Dependency Injection

모델 싱글톤 + Depends

@lru_cache(maxsize=1)로 Qdrant 클라이언트·CLIP·YOLO를 프로세스당 1회만 로드. FastAPI는 Depends, Celery는 같은 캐시 함수를 직접 호출하여 재사용합니다. 라우터 import만으로 모델이 끌어올려지지 않습니다. 

@lru_cache(maxsize=1)
def get_qdrant_client() -> QdrantClient:
    return QdrantClient(url=config.QDRANT_HOST)

def get_qdrant(
    client: QdrantClient = Depends(get_qdrant_client),
) -> Qdrant:
    return Qdrant(client)
Lifespan

부팅 시 워밍업

asynccontextmanager 기반 lifespan으로 모델·클라이언트를 미리 로드, 종료 시 close.

async / threads

이벤트 루프 보호

YOLO·CLIP·Qdrant 같은 동기 호출을 asyncio.to_thread로 워커 스레드에 위임.

Celery

안전한 비동기 임베딩

prefetch=1, acks_late, soft/hard time limit. uuid5 결정적 ID로 멱등성 확보.

Errors

전역 예외 핸들러

BusinessException · ValidationError · HTTPException 분리, 응답 포맷 통일.

Layered Architecture

레이어 분리

api / core / infrastructure / services / worker — 라우터는 얇게, 서비스는 도메인 로직, infrastructure는 외부 자원 경계만 담당. 테스트는 app.dependency_overrides로 mock을 주입할 수 있도록 설계했습니다.

03 리팩터링: Before → After

초기 구조의 문제를 분석하고, DI · lifespan · asyncio 패턴으로 다시 빌드한 과정.

Before
  • 라우터 import 시점에 CLIP·YOLO 즉시 로드 (~890MB)
  • Qdrant 클라이언트가 매 서비스 인스턴스마다 재생성
  • async def 안에서 동기 GPU 호출 → 이벤트 루프 블로킹
  • 라우터 모듈 싱글톤 → 테스트에서 mock 주입 불가
  • Celery 워커도 매 태스크마다 모델 재로드
  • lifespan 부재 → 첫 요청마다 콜드 스타트
After
  • lru_cache + lifespan 워밍업 → 프로세스당 1회 로드
  • Qdrant 클라이언트 단일 인스턴스, FastAPI/Celery 양쪽에서 재사용
  • asyncio.to_thread로 동기 호출 분리 → 동시 요청 처리 가능
  • Depends 기반 DI → app.dependency_overrides로 mock 주입
  • 같은 캐시 함수 호출로 워커 프로세스당 1회 로드
  • uuid5 결정적 ID + acks_late로 재시도 안전성 확보
