유사 이미지 검색_

업로드한 이미지의 객체를 판별하여 가장 유사한 이미지들을 반환합니다. YOLOv8 객체 검출 → CLIP ViT-L/14 768차원 임베딩 → Qdrant 코사인 유사도 검색을 단일 API 로 구현했습니다. 무거운 모델은 lru_cache + lifespan 으로 프로세스당 한 번만 로드합니다.

02 overview

검색 / 임베딩 두 가지 처리 흐름

사용자 검색은 POST /image/ 한 번으로 즉시 응답하고, 데이터셋 적재(스캔 → YOLO → CLIP → upsert)는 Celery 워커가 백그라운드로 처리합니다. 두 흐름 모두 같은 모델 싱글톤(@lru_cache)을 공유합니다.

유사 이미지 검색 흐름 · POST /api/v1/image/

[Client]        [FastAPI]             [Storage]         [Qdrant]
   │               │                     │                 │
   │ POST /image   │                     │                 │
   ├──────────────►│                     │                 │
   │               │ validate file       │                 │
   │               │ save temp           ├───────────────► │
   │               │                     │                 │
   │               │ asyncio.to_thread() │                 │
   │               │   ├─ YOLO detect    │                 │
   │               │   │   → bbox        │                 │
   │               │   ├─ size/ratio 검증│                 │
   │               │   └─ CLIP encode    │                 │
   │               │       → 768-dim     │                 │
   │               │                     │                 │
   │               │ Qdrant search       ├───────────────► │
   │               │ (top_k=5, cosine)   │                 │
   │               │                     │ ◄───────────────┤
   │               │ delete temp         │                 │
   │               │                     │                 │
   │ {images[...]} │                     │                 │
   │◄──────────────┤                     │                 │

YOLO · CLIP · Qdrant 호출은 모두 sync. async 라우터에서 직접 부르면 이벤트 루프가 멈추므로 asyncio.to_thread() 로 워커 스레드에 격리해 동시 요청 처리 능력을 유지합니다. finally 의 임시 파일 정리로 예외 발생 시에도 업로드 파일이 누적되지 않습니다.

데이터셋 임베딩 흐름 · embed_fruit_images() (Celery)

[Celery Worker]        [Storage]            [Qdrant]
       │                   │                    │
       │ embed_fruit_      │                    │
       │  images()         │                    │
       │ ─────────────────►│                    │
       │  scan images      │                    │
       │  (storage/images/ │                    │
       │   fruits/)        │                    │
       │                   │                    │
       │ for each image:   │                    │
       │   YOLO detect → bbox                   │
       │   size/ratio 검증                       │
       │   CLIP encode → 768-dim                │
       │   PointStruct(                         │
       │     id=uuid5(NAMESPACE_URL,            │
       │              image_path.name),         │
       │     vector=[...],                      │
       │     payload={image_url, bbox}          │
       │   )                                    │
       │                                        │
       │ qdrant.upsert_points(                  │
       │   collection_name="fruits",            │
       │   points=[...]                         │
       │ ) ────────────────────────────────────►│
       │                                        │
03 highlights

기술적 결정

001

의존성 주입 + 모델 싱글톤

CLIP ViT-L/14 · YOLOv8 · Qdrant 클라이언트는 메모리·초기화 비용이 큰 자원. 매 요청마다 새로 만들면 응답 시간이 폭증하므로 get_qdrant_client · get_embedding_model · get_yolo_model 을 @lru_cache(maxsize=1) 로 감싸 프로세스당 1회만 로드합니다. FastAPI 라우터는 Depends 로, Celery 워커는 같은 캐시 함수를 직접 호출해 동일한 모델 인스턴스를 공유합니다.

lru_cache depends singleton
002

lifespan 워밍업으로 콜드 스타트 제거

@asynccontextmanager 기반 lifespan 에서 부팅 시 Qdrant 클라이언트 · CLIP · YOLO 를 미리 로드합니다. 첫 요청에서 추론과 모델 로드가 동시에 발생하면 수 초의 지연이 생기는데, 워밍업으로 이 콜드 스타트를 완전히 차단. 종료 시점에는 Qdrant 클라이언트를 명시적으로 close() 해 graceful shutdown.

lifespan cold-start graceful shutdown
003

입력 검증 — bbox 임계치

YOLO 가 검출한 객체가 너무 작거나(점·반점 수준) 비율이 비정상이면 CLIP 임베딩이 노이즈가 되어 무관한 이미지를 매칭하기 쉽습니다. min_size=10px · min_ratio=0.01 임계치로 사전 필터링하고, 미달 시 BusinessException 으로 422 를 반환해 노이즈 벡터가 검색 흐름에 진입하지 못하게 차단합니다.

validation bbox noise-guard

Qdrant 컬렉션 자동 생성

현재 fruits 컬렉션이 사전 생성되어 있어야 동작. lifespan 에서 collection_exists("fruits") 검사 후 없으면 create_collection(size=768, distance="Cosine") 호출로 부트스트랩.

bootstrap lifespan
P0

응답 스키마 정합성 보정

response_model=ImageSearchResponse(SuccessResponse[dict]) 인데 실제 데이터는 list[dict]. 제네릭을 SuccessResponse[list[ImageHit]] 로 정정 + Pydantic 모델 정의.

pydantic contract
P1

Celery 워커 안정성 보강

task_acks_late · worker_prefetch_multiplier=1 · task_time_limit 정책 추가. GPU 작업이 멈추거나 워커가 죽었을 때 안전한 재처리 보장.

acks_late prefetch time-limit
P1

검색 도메인 추상화

현재 서비스명·컬렉션 키가 fruit 으로 하드코딩. ImageSearchService(collection: str) 식으로 컬렉션을 인자화해 신규 도메인(예: cars)을 클래스 추가 없이 확장 가능하게.

refactor domain

테스트 작성 — DI mock 활용

tests/ 디렉터리가 비어 있음. app.dependency_overrides[get_qdrant_client] 로 mock 주입해 라우터·서비스 단위 테스트 작성. 모델은 stub 으로 대체해 외부 자원 없이 실행.

pytest overrides mock

임계치 설정 외부화
