개발 노트 RAG 챗봇_

개발하며 정리한 노트를 모아둔 dev-notes 저장소를 gemini-embedding-001 로 임베딩해 Pinecone 벡터DB 에 적재하고, 사용자가 질문하면 검색하여 Gemini 가 근거와 함께 답변을 하는 서버리스 RAG 챗봇입니다. Vercel 서버리스 함수로 배포해 상시 구동 서버 없이 운영합니다. main 브랜치에 머지되면 Vercel이 빌드부터 배포까지 자동으로 처리합니다. 바이브 코딩으로 만든 프로젝트라, 평소 다루던 백엔드 스택이 아닌 Next.js · TypeScript 환경을 AI 페어 프로그래밍으로 빠르게 구축했습니다.

02 overview

쓰기와 읽기의 분리 · index → search → answer

대상은 dev-notes 저장소입니다. FastAPI · SQLAlchemy · Docker 처럼 주제별 폴더로 나눈 노트와 날짜별 개발 로그를 합쳐 마크다운 20여 개가 들어 있고, 노트를 쓸 때마다 늘어납니다.

그래서 인덱싱(쓰기)과 채팅(읽기)을 완전히 분리했습니다. 인덱싱은 노트가 늘었을 때만 로컬에서 돌리는 일회성 배치이고, 서버리스 함수로 배포되는 건 채팅 경로뿐입니다. 무거운 임베딩 작업이 사용자 요청 경로에 얹히지 않습니다.

인덱싱 · npm run index:github (로컬 수동 실행)

   GitHub repo ─┐
   로컬 폴더   ─┼─► 문서 수집 (.md / .txt)
   Google Drive ┘        │
                         ▼
                  manifest 대조
                         │        .indexed-github.json 에 기록된 파일은 skip → 증분 인덱싱
                         ▼
                  chunkText(size=1000, overlap=150)
                         │        청크 경계에 걸친 내용도 잡히도록 150자 오버랩
                         ▼
                  embed(chunk, "RETRIEVAL_DOCUMENT")
                         │        gemini-embedding-001 · 768차원 · L2 수동 정규화
                         ▼
                  vectorId = "gh:" + sha1(path) + ":" + i
                         │        한글 경로 → 결정적 ASCII ID (재실행 시 덮어쓰기)
                         ▼
                  Pinecone upsert
                                  100개 배치 · 파일 1개 끝날 때마다 manifest 저장
                                  → 중간에 끊겨도 다시 돌리면 이어서 진행

문서는 1000자 단위로 자르되 앞뒤 150자를 겹쳐서 나눕니다. 겹치지 않으면 한 문단이 청크 경계에서 두 동강 나, 어느 쪽에도 온전히 담기지 않아 검색에서 놓치게 됩니다. Pinecone 에는 100개씩 묶어 보내고, 파일 하나가 끝날 때마다 진행 상황을 저장합니다. 벡터 ID 규칙과 정규화는 아래 highlights 에서 다룹니다.

채팅 · POST /api/chat (Vercel 서버리스 함수)

   브라우저
      │  ① 질문
      ▼
   route.ts
      │  ② embed(question, "RETRIEVAL_QUERY")
      │        저장은 DOCUMENT, 검색은 QUERY 로 task type 을 나눠 검색 품질 확보
      ▼
   Pinecone query(topK=5, includeMetadata)
      │  ③ 관련 청크 + fileName + score
      ▼
   chat(question, context)
      │        gemini-3.5-flash-lite 로 먼저 시도
      │        ↪ 429 / 500 / 503 → withRetry 2·4·8·16s 지수 백오프 (최대 5회)
      │        ↪ 그래도 실패 → gemini-3.5-flash → gemini-3.6-flash 로 폴백
      ▼
   답변(GFM 마크다운) + 출처 링크
      │        react-markdown + remark-gfm 로 표·코드펜스 렌더링
      │        rehype-raw 는 의도적으로 미사용 → 노트 속 HTML 은 이스케이프 (XSS 차단)
      ▼
   브라우저

프롬프트에서 «자료에 없는 내용은 추측하지 말고 모른다고 답하라» 를 명시해 환각을 억제하고, 답변과 함께 근거가 된 노트를 출처 링크로 함께 내려 사용자가 직접 원문을 확인할 수 있게 했습니다. 예외는 route.ts 에서 사용자용 문구로 치환하고, 원문은 개발 환경에서만 detail 필드로 내려보냅니다.

현재 route.ts 는 score 와 무관하게 무조건 top-5 를 가져와, «모른다» 고 답하면서도 출처 5개가 붙습니다. 실측 분포상 경계가 0.6 부근이므로 MIN_SCORE = 0.6 필터 + 결과 0건일 때 전용 응답으로 교체할 예정.

P1

프론트매터 · 위키링크 전처리

노트는 Obsidian 형식이라 파일 맨 위에 tags·created YAML 블록이 붙고, 본문에는 [[다른 노트]] 링크가 섞여 있습니다. 지금은 이게 그대로 임베딩돼 첫 청크에 노이즈가 들어갑니다. 프론트매터는 본문에서 떼어내 메타데이터로 넘기고, 위키링크는 텍스트만 남기도록 정리할 예정.
