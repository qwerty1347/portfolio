LLM 에이전트 챗봇_

Groq Llama 3.1-8B가 사용자의 질문을 일상 대화/정보 요청으로 1차 분류한 뒤, 정보 요청이면 LangChain ReAct 에이전트가 Qdrant 벡터 검색과 SerpAPI 웹 검색 도구를 스스로 선택해 호출합니다. 모든 외부 자원은 @lru_cache + lifespan으로 프로세스당 1회만 로드되고, 동기 LLM 호출은 asyncio.to_thread로 격리되어 이벤트 루프를 보호합니다.

04 // highlights

기술적 결정

001

Tool DI — 클로저 팩토리 패턴

ChatAgentService가 qdrant·embedding_model을 직접 소유하던 leaky abstraction을 제거. build_db_search(db_search)가 의존성을 클로저로 캡처해 @tool 함수를 반환하므로 LLM 에게는 query: str만 노출되고, Service 시그니처는 LLM·Tools·Memory만 안다.

DI closure factory
002

의존성 주입 + 모델 싱글톤

get_qdrant_client · get_embedding_model · get_groq를 @lru_cache(maxsize=1)로 감싸 프로세스당 1회만 로드. FastAPI는 Depends로, Celery 워커는 같은 캐시 함수를 직접 호출하여 완전히 동일한 객체를 재사용. 라우터 import만으로 SentenceTransformer가 끌려오지 않는다.

lru_cache singleton DI
003

AgentExecutor + ReAct 프롬프트 캐싱

기존엔 매 요청마다 hub.pull("hwchase17/react")를 호출하고 AgentExecutor를 새로 만들었다. REACT_PROMPT를 모듈 상수로 끌어올리고 ChatAgentService.__init__에서 Executor를 1회만 빌드, ainvoke로 재사용해 네트워크/조립 비용을 제거.

react cache init-time
004

lifespan 워밍업으로 콜드 스타트 제거

asynccontextmanager 기반 lifespan에서 부팅 시 Qdrant 클라이언트 · SentenceTransformer · Groq를 미리 로드. 첫 /api/v1/chat 요청에서 384차원 임베딩 모델 다운로드가 발생하지 않도록 차단. 종료 시 Qdrant client를 명시적으로 close.

lifespan cold-start
005

Chitchat vs RAG 자동 분기

"안녕"·"심심해"·"추천해줘" 같은 일상 대화에까지 ReAct 에이전트 + Qdrant 검색을 돌리면 비용·지연이 낭비된다. 1차 LLM 호출로 True/False를 받아 chitchat이면 친근체 응답만, 아니면 도구 사용 경로로 분기. 프롬프트는 Python Boolean 출력만 허용하도록 제약.

routing cost-aware
