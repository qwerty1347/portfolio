LLM 에이전트 챗봇_

→ ReAct agent · RAG + Web search · Chitchat-aware routing

Groq Llama 3.1-8B가 사용자의 질문을 일상 대화/정보 요청으로 1차 분류한 뒤, 정보 요청이면 LangChain ReAct 에이전트가 Qdrant 벡터 검색과 SerpAPI 웹 검색 도구를 스스로 선택해 호출합니다. 모든 외부 자원은 @lru_cache + lifespan으로 프로세스당 1회만 로드되고, 동기 LLM 호출은 asyncio.to_thread로 격리되어 이벤트 루프를 보호합니다.

1차 LLM 호출로 일상 대화(인사·잡담·감정·추천)로 분류되면 ReAct 에이전트를 건너뛰고 친근체 응답만 생성. 단기 메모리(deque(maxlen=10))의 직전 대화를 컨텍스트로 주입해 자연스러운 흐름 유지.

04 // highlights

기술적 의사결정

001

Tool DI — 클로저 팩토리 패턴

ChatAgentService가 qdrant·embedding_model을 직접 소유하던 leaky abstraction을 제거. build_db_search(db_search)가 의존성을 클로저로 캡처해 @tool 함수를 반환하므로 LLM 에게는 query: str만 노출되고, Service 시그니처는 LLM·Tools·Memory만 안다.

DI closure factory
002

의존성 주입 + 모델 싱글톤

get_qdrant_client · get_embedding_model · get_groq를 @lru_cache(maxsize=1)로 감싸 프로세스당 1회만 로드. FastAPI는 Depends로, Celery 워커는 같은 캐시 함수를 직접 호출하여 완전히 동일한 객체를 재사용. 라우터 import만으로 SentenceTransformer가 끌려오지 않는다.

lru_cache singleton DI
003

AgentExecutor + ReAct 프롬프트 캐싱

기존엔 매 요청마다 hub.pull("hwchase17/react")를 호출하고 AgentExecutor를 새로 만들었다. REACT_PROMPT를 모듈 상수로 끌어올리고 ChatAgentService.__init__에서 Executor를 1회만 빌드, ainvoke로 재사용해 네트워크/조립 비용을 제거.

react cache init-time
004

lifespan 워밍업으로 콜드 스타트 제거

asynccontextmanager 기반 lifespan에서 부팅 시 Qdrant 클라이언트 · SentenceTransformer · Groq를 미리 로드. 첫 /api/v1/chat 요청에서 384차원 임베딩 모델 다운로드가 발생하지 않도록 차단. 종료 시 Qdrant client를 명시적으로 close.

lifespan cold-start
005

Chitchat vs RAG 자동 분기

"안녕"·"심심해"·"추천해줘" 같은 일상 대화에까지 ReAct 에이전트 + Qdrant 검색을 돌리면 비용·지연이 낭비된다. 1차 LLM 호출로 True/False를 받아 chitchat이면 친근체 응답만, 아니면 도구 사용 경로로 분기. 프롬프트는 Python Boolean 출력만 허용하도록 제약.

routing cost-aware
006

Serp 어댑터 통합

원래 Serp(호출)와 SerpService(파싱)가 분리되어 있었지만 의존성이 0개인 순수 파서를 services/ 계층에 두는 게 어색했다. Serp 한 클래스로 통합하여 WebSearch의 DI를 (serp) 한 개로 축소하고 app/services/search/ 디렉터리를 삭제.

refactor cohesion
007

이벤트 루프 보호 — to_thread

Groq ChatGroq.invoke는 동기 호출이라 비동기 라우터에서 직접 부르면 이벤트 루프가 막힌다. handle_agent의 chitchat 분류, chitchat 응답, 결과 출력 LLM 호출을 모두 asyncio.to_thread(self.llm.run, ...)로 워커 스레드에 위임해 동시 요청 처리 가능.

asyncio non-blocking
008

Groq 래퍼의 leaky abstraction 제거

기존엔 self.llm.llm으로 내부 ChatGroq을 직접 꺼내 create_react_agent에 넘기는 코드가 있었다. 내부 필드를 _llm으로 캡슐화하고 get_chat_model() -> ChatGroq getter를 노출해 외부에 LangChain Runnable 인터페이스를 명시적으로 공개.

encapsulation getter

에이전트 처리 흐름 — 핵심 코드

// app/services/agent/chat.py · chitchat 분기 + 캐시된 ReAct Executor

chat.py tool.py chat (deps).py 
# 모듈 로드 시 1회 — 네트워크 hub.pull 비용 제거
REACT_PROMPT = hub.pull("hwchase17/react")


class ChatAgentService:
    def __init__(self, agent_tools, llm: Groq, max_iterations: int = 1):
        self.agent_tools = agent_tools
        self.llm = llm
        self.short_term_memory = ShortTermMemory()
        # __init__에서 1회 — 요청마다 재생성하지 않음
        self.agent_executor = self._build_agent_executor(max_iterations)

    async def handle_agent(self, user_input: str):
        self.short_term_memory.buffer.append({"role": "user", "content": user_input})

        # 1. chitchat 여부 1차 분류 (LLM)
        chitchat_output = await asyncio.to_thread(
            self.llm.run, chitchat_prompt, user_input,
        )

        if self.is_chitchat(chitchat_output):
            # 2a. 일상 대화 — 친근체 응답만 생성
            agent_output = await asyncio.to_thread(self.llm.run, ...)
        else:
            # 2b. 정보 요청 — ReAct Executor가 도구 자율 선택
            result = await self.agent_executor.ainvoke({"input": user_input})
            tool_result = [obs for _, obs in result["intermediate_steps"]]
            agent_output = await asyncio.to_thread(
                self.llm.run, result_prompt, user_input,
                context=tool_result, history=short_term_history,
            )
        return getattr(agent_output, "content", "")
