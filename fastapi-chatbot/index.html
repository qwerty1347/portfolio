LLM 에이전트 챗봇_

Llama 3.1-8B 가 사용자의 질문을 일상 대화 / 정보 요청으로 1차 분류한 뒤, 정보 요청이면 LangChain ReAct 에이전트가 Qdrant 벡터 검색과 SerpAPI 웹 검색 도구를 스스로 선택해 호출합니다. 모든 외부 자원은 @lru_cache + lifespan 으로 프로세스당 1회만 로드되고, 동기 LLM 호출은 asyncio.to_thread 로 격리되어 이벤트 루프를 보호합니다.

02 overview

Chitchat 분기 + ReAct 도구 선택

1차 LLM 호출로 True/False 만 받아 chitchat 분기와 RAG 분기를 가르고, RAG 쪽은 ReAct 에이전트가 두 도구(use_db_tool / use_web_tool) 중 description 만 보고 자율 선택해 호출합니다.

Chat 요청 처리 흐름 · POST /api/v1/chat/

[Client]        [FastAPI]              [LLM]            [Qdrant / Serp]
   │               │                     │                     │
   │ POST /chat/   │                     │                     │
   ├──────────────►│                     │                     │
   │               │ buffer.append(user) │                     │
   │               │                     │                     │
   │               │ 1) chitchat 판정    │                     │
   │               │ asyncio.to_thread() ├────────────────────►│
   │               │                     │ "True" / "False"    │
   │               │                     │◄────────────────────┤
   │               │                                           │
   │               │ ┌─ True (일상 대화) ─────────────────┐    │
   │               │ │ chitchat output 프롬프트로         │    │
   │               │ │ history + user → LLM 답변 생성     │    │
   │               │ └────────────────────────────────────┘    │
   │               │                                           │
   │               │ ┌─ False (정보 요청) ────────────────┐    │
   │               │ │ AgentExecutor.ainvoke({input})     │    │
   │               │ │ ReAct: tool 선택 → 호출 → 관찰     │    │
   │               │ │  └─ use_db_tool ───► Qdrant 검색   │    │
   │               │ │  └─ use_web_tool ──► SerpAPI 호출  │    │
   │               │ │                                    │    │
   │               │ │ result output 프롬프트로           │    │
   │               │ │ context + history + user → 최종 답 │    │
   │               │ └────────────────────────────────────┘    │
   │               │                                           │
   │               │ buffer.append(assistant)                  │
   │ { data }      │                                           │
   │◄──────────────┤                                           │

동기 LLM 호출(chain.invoke) 은 모두 asyncio.to_thread() 로 워커 스레드에 격리되어 async 라우터의 이벤트 루프를 점유하지 않습니다. 단기 메모리(deque(maxlen=10)) 의 직전 대화가 양 분기 모두에 history 로 주입됩니다.

ReAct 에이전트 도구 선택 흐름 · AgentExecutor.ainvoke()

[AgentExecutor.ainvoke(input)]
       │
       │ REACT_PROMPT (hwchase17/react · 모듈 로드 시 1회 fetch)
       │ + tools description
       │   ├─ use_db_tool:  "내부 DB 검색에 사용."
       │   └─ use_web_tool: "내부 DB 외 검색에 사용."
       │
       ▼
[LLM 1차 추론]
       │
       │ Thought: 이 질문은 도매꾹과 관련이 ...
       │ Action: use_db_tool / use_web_tool
       │ Action Input: "..."
       │
       ▼
[Tool 실행 — 클로저로 주입된 DBSearch / WebSearch]
       │
       │ DBSearch.search_qdrant(query)
       │   → SentenceTransformer.encode (384-dim)
       │   → qdrant.find_points("board_notice", top_k=5)
       │
       │ WebSearch.search_serp(query)
       │   → SerpAPIWrapper(google, hl=ko, gl=kr)
       │   → knowledge_graph + organic_results 상위 3개 파싱
       │
       ▼
[intermediate_steps 에 (action, observation) 누적]
       │
       │ max_iterations=1 → 1회만 도구 호출
       │
       ▼
[result['intermediate_steps'] 의 observation 만 추출 → context]

도구는 build_db_search(db_search) 같은 클로저 팩토리로 의존성을 캡처해 LLM 에는 query: str 시그니처만 노출합니다. description 이 LLM 의 도구 선택 단서이므로, 도구 추가 시 description 작성이 가장 중요한 작업이 됩니다.

03 highlights

기술적 결정

001

Tool DI — 클로저 팩토리 패턴

ChatAgentService 가 qdrant · embedding_model 을 직접 소유하던 leaky abstraction 을 제거. build_db_search(db_search) 가 의존성을 클로저로 캡처 해 @tool 함수를 반환하므로 LLM 에게는 query: str 만 노출되고, Service 시그니처는 LLM · Tools · Memory 만 안다.

DI closure factory
002

의존성 주입 + 모델 싱글톤

get_qdrant_client · get_embedding_model · get_groq 를 @lru_cache(maxsize=1) 로 감싸 프로세스당 1회만 로드. FastAPI 는 Depends 로, Celery 워커는 같은 캐시 함수를 직접 호출하여 완전히 동일한 객체를 재사용. 라우터 import 만으로 SentenceTransformer 가 끌려오지 않는다.

lru_cache singleton DI
003

AgentExecutor + ReAct 프롬프트 캐싱

기존엔 매 요청마다 hub.pull("hwchase17/react") 를 호출하고 AgentExecutor 를 새로 만들었다. REACT_PROMPT 를 모듈 상수로 끌어올리고 ChatAgentService.__init__ 에서 Executor 를 1회만 빌드, ainvoke 로 재사용해 네트워크 / 조립 비용을 제거.

react cache init-time
004

lifespan 워밍업으로 콜드 스타트 제거

@asynccontextmanager 기반 lifespan 에서 부팅 시 Qdrant 클라이언트 · SentenceTransformer · Groq 를 미리 로드. 첫 /api/v1/chat 요청에서 384차원 임베딩 모델 다운로드가 발생하지 않도록 차단. 종료 시 Qdrant client 를 명시적으로 close.

lifespan cold-start
005

Chitchat vs RAG 자동 분기

"안녕" · "심심해" · "추천해줘" 같은 일상 대화에까지 ReAct 에이전트 + Qdrant 검색을 돌리면 비용 · 지연이 낭비된다. 1차 LLM 호출로 True/False 를 받아 chitchat 이면 친근체 응답만, 아니면 도구 사용 경로로 분기. 프롬프트는 Python Boolean 출력만 허용하도록 제약.

routing cost-aware
